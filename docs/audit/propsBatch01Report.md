# Props batch 01 — audit

`aiagent_props_batch_01.zip`, received 2026-11-07. Ten props: the five shared
Code/Test items, the printer, the filing cabinet, the hydrangea and the two
Library shelves.

**Verdict: not installed.** Every technical requirement passes. It fails on
sight, and the reason is partly that `docs/PROP_BRIEF.md` told it to — see
"What the brief got wrong" below. `web/assets` was not touched.

## Technical QA — passes, measured from the pixels

| Check | Result |
|---|---|
| Width matches the brief | **10/10 exact** — 680, 680, 680, 790, 440, 360, 280, 260, 240, 180 |
| Real alpha channel | 10/10 |
| Alpha bounding box == canvas (no padding) | 10/10 |
| Subject touches the bottom edge | 10/10 |
| File name passes the serving allowlist | 10/10 |
| One object per file, not a sheet | 10/10 |

`shelf-big` and `shelf-tall` are 99.7% and 99.5% opaque. That is not a defect —
a bookcase is a rectangle — and `TestPropsAreCutOut` only requires one
transparent pixel, so they would pass the suite.

This is the first delivery where the numbers were right on the first pass.

## Visual QA — fails

Evidence, all generated by composing the real `roomDefs` positions over the
real `bg-*.jpg`:

- [props-batch01-rooms.jpg](props-batch01-rooms.jpg) — code, test and library,
  current props beside the new ones, same scale, same background
- [props-batch01-side.jpg](props-batch01-side.jpg) — six props, old next to new
- [props-current.jpg](props-current.jpg) — all 39 props that ship today
- [room-light-reference.jpg](room-light-reference.jpg) — the eight backgrounds

Three problems, in order of severity.

**1. Flat vector against painted illustration.** The rooms are painted: soft
shading, bounced light, reflective floors. The batch is flat fill plus a hard
dark outline. In the room it reads as a UI widget pasted onto a photograph, not
as furniture standing in the room. The package README says this plainly —
"original stylised neon-vector candidates, not the cinematic illustrated
character-matched final art" — and it is right.

**2. The props lost their contents.** `desk-blue2` today is a desk *and* a
chair, a monitor, a small robot, a stack of books and a plant. The new one is a
bare desk with two flat monitors. `shelf-big` today is a wooden bookcase with
books, a lamp, a framed picture, storage boxes and a trailing vine; the new one
is a black rectangle with coloured bars. Swapping them empties the rooms — the
chairs and the robots simply disappear, and nothing else puts them back.

**3. The palette fights the rooms.** Every prop is dark navy with a thin neon
edge. Of the three rooms tested, that works in `code` and loses in both others:
`test` is a bright white lab, so the dark desks punch holes in it, and
`library` is warm amber wood, so the black shelves read as empty slabs.

Per-prop:

| Prop | Call |
|---|---|
| `printer2` | closest to usable; silhouette and detail survive |
| `filing-blue` | usable shape, wrong value for a white lab |
| `hydrangea` | reads as lollipops rather than hydrangea, but it is a flower |
| `desk-blue2` `-pink2` `-white2` | lose the chair, the robot, the plant and the books |
| `shelf-big` `shelf-tall` | read as a chart widget, not a bookcase |
| `cactus` | thin and flat; the pot is an empty bowl |
| `plant-big` | **does not read as a plant** — a pink and teal fan on a stalk |

## What the brief got wrong

`PROP_BRIEF.md` §2 said the rooms are "navy with neon signage" and asked for
props "lit by the room, not by daylight" with a cool ambient and a saturated
rim. That description fits `code` and `ops` and **no other room**. Rendering
all eight backgrounds side by side shows the spread: `test` is a high-key white
and cyan lab, `library` is warm amber lantern-lit wood, `approval` is pale
mint, `lounge` is rose and peach. Six of the eight are bright, warm or both.

The brief also never said what each file contains, so "redraw `desk-blue2`" was
reasonably read as "draw a desk".

Both are fixed in the brief as of this commit. The batch did what it was told.

## What to ask for next

Same ten files, same sizes — the sizes are correct and should not change.
Changed instructions:

1. Painted, not vector: soft shading and a light direction, the same technique
   as `props-current.jpg`.
2. Keep everything the current prop contains. `props-current.jpg` is the
   inventory; the new drawing must hold the same objects.
3. Match the room's own light, per the table in the brief — not one dark
   palette for all eight.
